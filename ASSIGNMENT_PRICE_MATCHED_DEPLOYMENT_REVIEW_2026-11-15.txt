Date: 2026-11-15

DECISION
FAIL the unchanged primary median-latency screen in both initializations when
candidate and references receive the same CPU compilation opportunity.
Storage and p95 pass. Reference correctness tests and independent artifact
audit pass. Do not promote the prior unmatched-runtime pass to a controlled
architecture-efficiency claim. Hold simulator integration and research training.

WHAT WAS IMPLEMENTED
assignment_price_reference_deployment.py exports the existing reference neural
cores to ONNX and reuses their existing native validation/decoder. It covers
screened_price24, unmasked_compact64, screened_wide128 and unmasked_wide128.
The compact outer softplus, wide branch maximization, original price formula,
observed-state local mask and horizon factor are retained. FP32 reference
arithmetic remains FP32; ADP's declared FP32 heads/FP64 costs remain unchanged.
Both use the same CPUExecutionProvider, graph optimization options, single
intra/inter-op threads and native compiler settings. No models were redesigned
and no training/rewards/seeds/thresholds were modified.

REFERENCE EQUIVALENCE TESTS
Three test groups passed, zero errors/failures:
- Four references x two saved untrained checkpoints x 128 shared observations:
  1,024 exact-action checks against original runtime and original eager critic.
  Chosen values agree at existing atol 1e-6/rtol 1e-5. Model hashes unchanged.
- Equal-weight ties, adjacent-FP32 biases and returned-array ownership.
- Nonfinite, terminal/off-grid and invalid task inputs, wrong dtype/shape and

Candidate deployment source remains the previously tested version. Candidate
and reference setup supplied 2,048 additional model/state checks before timing.
These establish equivalence on fixtures, not all possible trained near ties.
The deployments are immutable snapshots and require export after weight updates.

The primary is 1.67 and 1.78 times the unmasked-wide median. Against screened

The earlier CPU deployment comparison passed against references using their
previous runtime. That result is preserved with its actual scope. This new
comparison shows that its speed advantage does not survive equal compilation.
It does not imply that the controller cannot learn good offloading policies;
there is still no new policy-quality evidence. Removing the sweep cannot be
selected from these outcomes to redefine the primary retrospectively.

ARTIFACT AUDIT
audit_assignment_price_matched_deployment.py independently verified the saved
manifest, original test/cost manifests, tested/current source hashes, sixteen
checkpoint hashes, sixteen ONNX graph hashes and ONNX validity. All graph
FP32 initializer tensors match their source checkpoint weights exactly; sizes
and parameter/buffer payloads checked. Independent statistics and percentile
interpolation reproduce all raw timing rows, shuffle order, medians/p95 and
the failed screens. Audit PASS; no model timing rerun in the audit.

Primary parameter payload 68,264 bytes plus 20 external scale-buffer bytes;
serialized heads 74,164 bytes. Serialized compact graph 196,238 bytes; wide
423,316 bytes; original price 68,815 bytes plus its external scale convention.
Graph/tensor payload excludes shared runtime libraries, workspace and actual
peak process memory. First-action records share process/import caches and do
not establish cold deployment startup. Candidate and original price retain
their existing distinct numerical cost precision; compiler opportunity, not
controller arithmetic, is matched. The predeclared precision text refers to
frozen original control arithmetic; control_scope and actual source explicitly
state ONNX/native for all paths in this comparison.

NEXT DECISION
Do not launch simulator integration or training under the current failed gate.
Preserve the smaller-storage result without claiming a proven lightweight or
low-complexity contribution. A bounded next engineering investigation can
profile the matched primary and wide reference to identify whether graph output
conversion, native-call boundaries or actual decoder work account for the
remaining gap. Those causes have not been established by this benchmark.
Use a concrete measured bottleneck to decide one equivalent optimization or
stop this implementation route; do not start another scientific redesign or
repeat unchanged acceptance timings. Any later version needs declared tests,
matched references and unchanged limits before measurement. If no justified
optimization remains, revisit the contribution decision brief explicitly rather
than weaken criteria retrospectively or run a costly trial that fails the gate.

Zero new simulator steps, optimizer updates, research training or research seed
use. Final evaluation seeds and Word thesis remain untouched. Novelty, policy
quality, value calibration and the eventual thesis claim remain unproven.
Security/trust, cloud and charging remain excluded from this contribution.
