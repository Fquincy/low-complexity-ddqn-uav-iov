QUESTION AND CLAIM BOUNDARY
Can the restricted exact movement-conditioned model reduce online parameter
storage relative to the original additive128 DDQN while preserving a useful
policy, despite a measured inference-latency penalty? This is a bounded
engineering quality/cost screen. It cannot prove novelty, deployment
low-complexity or general noninferiority.

FROZEN ARMS
1. additive128: existing factorized DDQN,128x128.
2. additive64: same factorized DDQN at64x64; controls for the effect of shrinking
   the network.
3. emc_q_original_exact: fixed EMC-Q with original einsum exact decoder.
Do not select matmul/broadcast after examining quality; variants remain profile
references. Physical model, task generator, reward equations, state, legal
actions, horizon and simulator version stay fixed.

PREDECLARED ENGINEERING SCREEN
All three EMC initialization replicates must pass. Paired per-episode return is
sum of 40 slot rewards; higher/closer to zero is better. Deadline success is
on-time tasks / all generated tasks across the complete episode, not the mean
of partial cumulative slot ratios.

Versus additive128: mean episode-return difference >=-2 reward units AND
absolute deadline-success fraction difference >=-.01 (minus1 percentage point).
Versus additive64: mean return difference >=+2 units AND deadline fraction
>=+.01. Against EACH nearest-RSU and UAV-selective heuristic: neither metric
below that heuristic. All three conditions use point estimates as development
screens, not formal noninferiority claims or significance tests.

Calibration screen for all EMC seeds: own greedy final-slot stage0 and stage31
absolute value error p95<=10 versus realized final-slot reward; fixed-probe
positive greedy Q fractions stage0 and stage31 each<=5%. These are diagnostics,
not sufficient quality criteria.

Storage screen: EMC online parameter bytes<=70% of additive128. Cost screen:
complete-action median<=5x additive128 and p95<=2.0ms on the declared local CPU
protocol. The p95 ceiling is a local engineering limit, not an application
real-time guarantee. Report additive64, SPI reference and every raw duration.
There is no claim about peak process memory or energy. Include online, target,
optimizer and replay-array bytes and wall time for training/evaluation.

The quality thresholds deliberately include an EMC benefit over compact
additive64, because EMC currently uses42.3% more parameter bytes and has a
latency cost. If these margins are not acceptable to the supervisor, renegotiate
and freeze them BEFORE launching the runner, not after seeing outcomes.
