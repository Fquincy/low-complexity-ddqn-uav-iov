CONFIRMED LAUNCH BLOCKERS
1. The runner verifies the older compatibility manifest against the current
   root, including LOW_COMPLEXITY_PROJECT_STATUS.json. That status file was
   legitimately advanced when preparation completed. Of 114 compatibility
   manifest entries it is the only mismatch. The archived status in the
   retained fixture matches the original manifest, so this is an evidence
   reference bug rather than lost historical evidence. A new execution would
   fail before training. Use an explicit archived-evidence mapping and keep
   the current status separately; preserve the original manifests and bytes.

2. frozen_inference_gate measures action latency at runner line 249, then
   writes PRE_TIMING_FREEZE.json at line 254 after the fit loop finishes.
   Freeze exported graphs, extra decoder arrays, execution settings and
   measurement order before the first timed call. Record and audit the stage
   ordering; the present file name alone does not establish that ordering.

3. The runner's overall development pass uses all(quality_screens.values()),
   which excludes the separately computed storage/latency screens. The full
   research auditor repeats that omission in research_claim_established.
   Therefore a cost failure could coexist with an overall success label.
   Require every predeclared quality AND cost condition in the aggregate
   decision. Rename the claim label to describe empirical protocol screens;
   passing them does not independently establish novelty or thesis sufficiency.

4. Existing tests execute audit_fixture, not audit_research. The one-fit,
   one-episode fixture does not exercise multi-fit grouping, multi-episode
   schedules or diagnostic-validation orchestration. Add a reduced, explicitly
   synthetic multi-fit/multi-episode plan using the same research orchestration
   and audit implementation, with safe nonreserved seeds. Verify expected
   counts from the plan, exact episode/fit identities, checkpoint inventory,
   action/workload pairing, greedy evaluation actions, immutable weights,
   comparisons, value summaries and inference-stage ordering. Test deliberate
   corruption and a cost failure, rather than only the passing case.
